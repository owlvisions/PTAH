# PTAH evidence interoperability with the baseline runtime

## Status

The TypeScript adapter in `src/application/investigation/PtahEvidenceAdapter.ts` converts the portable PTAH v1 evidence-summary format into the existing baseline `EvidenceBundle` contract. It uses the baseline `createEvidence` and `createEvidenceBundle` functions, so semantic IDs and bundle manifests are generated by the original implementation rather than imitated in PTAH's dependency-free runtime.

## Trust boundary

PTAH v1 records summaries, source labels, confidence, and a target SHA-256. It does not necessarily carry the original tool's raw output, authenticated provider identity, or proof that the provider actually ran. Accordingly, the adapter:

- labels imported records with `authority: "analyst-inference"`;
- retains the PTAH evidence ID, kind, and source label in the baseline record parameters;
- records explicit limitations about missing raw output and unverified provider execution;
- rejects records whose target digest differs from the investigation target;
- rejects duplicate PTAH evidence IDs and claims with dangling evidence references;
- returns an explicit PTAH-ID → baseline semantic-ID crosswalk;
- keeps claims in a separate export field rather than incorrectly treating claims as evidence records.

This is a loss-aware import bridge, not a claim that PTAH's summaries are equivalent to raw observations. A later provider-runner integration should emit native Evidence directly from authenticated provider results and should avoid this summary adapter for those observations.

## Validation

`PtahEvidenceAdapter.test.ts` covers conversion, EvidenceLedger import, ID crosswalk, trust limitations, stale-target rejection, dangling references, and duplicate IDs. These tests require the repository's normal TypeScript/Vitest dependencies and supported Node version; they cannot be reported as executed when that environment is unavailable. The dependency-free PTAH tests are run separately with `npm run test:ptah`.
